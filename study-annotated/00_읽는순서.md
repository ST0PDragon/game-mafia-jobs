# 서버 코드 주석판: 읽는 순서와 전체 구조

이 폴더는 `server/` 코드를 공부하려고 만든 **복사본**입니다. 여기 있는 파일을 고쳐도 실제 서버에는 아무 영향이 없습니다.
(Maven은 `server/src`만 컴파일하고, Unity는 `Assets/`만 읽기 때문에 이 폴더는 빌드에 끼어들지 않습니다.)

- 원래 있던 주석은 그대로 두었습니다.
- 새로 단 설명은 대부분 코드 **윗줄**에 있고, 짧은 줄은 줄 끝에 붙였습니다.
- `⚠`로 시작하는 주석은 지난번 리뷰에서 보완점으로 짚었던 부분입니다.
- 주석과 공백을 빼고 비교하면 코드는 원본과 똑같습니다(자바는 토큰 단위, SQL·YAML은 내용 단위로 비교해 확인했습니다).

---

## 1. 이 서버가 하는 일 (한 문장)

> 해적 마피아 게임에서 **"내 직업 확인 → 능력 사용 제출 → 밤에 한꺼번에 판정 → 나에게 공개된 결과만 조회"** 를 처리하는 REST API 서버입니다.

아직 없는 것: 방 만들기/참가, 직업 배정, 낮 투표, 단계 타이머, 로그인(JWT 발급).
→ 그래서 지금은 **테스트 코드가 직접 방과 플레이어를 DB에 넣고** 기능을 확인합니다.

## 2. 폴더(레이어) 구조

```
요청(Unity) ─HTTP─▶ controller ─▶ service ─▶ repository ─▶ DB(H2 / PostgreSQL)
                        │             │            │
                        └──── dto ────┘         domain(Entity)
config: 보안(JWT) 설정           resources/db/migration: 테이블 만드는 SQL
```

| 레이어 | 파일 | 한 줄 역할 |
| --- | --- | --- |
| 시작점 | `MafiaServerApplication.java` | 스프링 부트 앱을 켠다 |
| config | `SecurityConfig.java` | 어떤 URL에 로그인(JWT)이 필요한지 정한다 |
| controller | `RoleController.java` | URL과 메서드를 연결하고, JWT에서 userId를 꺼낸다 |
| dto | `RoleApiDtos.java` | 주고받는 JSON 모양(record) |
| service | `RoleService.java` | 직업 조회, 행동 제출 검증·저장, 포수 즉시 사격 |
| service | `NightResolutionService.java` | 밤 행동 일괄 판정 (차단 → 보호 → 공격 → 조사 보고) |
| service | `RoomOutcomeService.java` | 승리 조건 검사, 플레이어 진영 계산 |
| domain | `*Entity.java`, enum | DB 테이블 한 줄 = 자바 객체 하나 |
| repository | `*Repository.java` | 메서드 이름만으로 SQL을 만들어 주는 Spring Data JPA 인터페이스 |
| test | `RoleApiIntegrationTest.java` | 규칙이 제대로 동작하는지 시나리오별로 검증 |
| resources | `application*.yml`, `V1~V3.sql` | DB 접속 정보, 테이블 생성/변경 SQL(Flyway) |

## 3. 추천 읽기 순서

1. **`resources/db/migration/V1 → V2 → V3.sql`**: 테이블이 어떻게 생겼는지 먼저 봅니다. 엔티티가 훨씬 쉽게 읽힙니다.
2. **`domain/`**: `RoomPhase`, `Faction` → `RoleEntity` → `RoomEntity` → `RoomPlayerEntity` → `RoomActionEntity` → `PirateAttackSelectionEntity` → `RoomReportEntity` → `ActionCode`
3. **`repository/`**: 메서드 이름 규칙(`findBy...OrderBy...`)만 익히면 금방 읽힙니다.
4. **`dto/RoleApiDtos.java`**: API가 주고받는 JSON 모양.
5. **`config/SecurityConfig.java` → `controller/RoleController.java`**: 요청이 들어오는 입구.
6. **`service/RoomOutcomeService.java`**: 짧아서 서비스 워밍업으로 좋습니다.
7. **`service/RoleService.java`**: 핵심 1. 특히 `submitAction`의 검증 순서.
8. **`service/NightResolutionService.java`**: 핵심 2. 밤 판정 순서.
9. **`test/RoleApiIntegrationTest.java`**: 위 규칙이 실제로 어떻게 쓰이는지 예제로 확인.

## 4. 요청 하나가 처리되는 흐름 (예: 선의가 3번을 보호)

```
POST /api/v1/games/12/actions
Authorization: Bearer <JWT, sub=100>
{"requestId":"7e28...","actionCode":"PROTECT","targetPlayerId":3}
```

1. **SecurityConfig**: JWT 서명이 맞는지 검사합니다. 틀리면 여기서 401.
2. **RoleController.submitAction**: JSON을 `SubmitActionRequest`로 바꾸고 `@Valid`로 빈 값을 검사합니다. JWT의 `sub`(100)를 userId로 꺼냅니다.
3. **RoleService.submitAction**
   1. 방을 **잠금**으로 읽습니다(`lockById`). 같은 방의 동시 요청이 한 줄로 섭니다.
   2. 같은 `requestId`로 이미 처리한 요청인지 봅니다. 그렇다면 예전 결과를 그대로 돌려줍니다(재시도 안전).
   3. 지금 단계에 쓸 수 있는 능력인지, 살아 있는지, 내 직업의 능력인지, 이번 라운드에 이미 냈는지, 횟수가 남았는지, 대상이 올바른지 차례로 검사합니다.
   4. `room_actions`에 저장하고 `202 Accepted`를 돌려줍니다. **효과는 아직 없습니다.**
4. (나중에 타이머가) **NightResolutionService.resolveNight(12)**
   1. 갑판장 차단 → 2. 방문 기록 → 3. 보호 목록 → 4. 해적 공격 → 5. 조사 보고 → 6. 승리 검사 → 낮으로 전환
5. Unity가 **GET `/me/reports`** 로 나에게 온 결과만 가져갑니다.

## 5. 꼭 알아야 할 개념 정리

| 개념 | 어디서 | 쉬운 설명 |
| --- | --- | --- |
| `@Entity` / JPA | domain | 자바 클래스 ↔ DB 테이블을 자동으로 연결. 필드를 바꾸면 트랜잭션이 끝날 때 UPDATE가 자동으로 나갑니다(**변경 감지**). |
| `protected` 기본 생성자 | 모든 Entity | JPA가 객체를 만들 때 필요. 개발자가 실수로 빈 객체를 만들지 못하게 `protected`로 둡니다. |
| Spring Data 메서드 이름 쿼리 | repository | `findByRoomIdAndUserId` → `WHERE room_id=? AND user_id=?`. 구현 코드가 없어도 됩니다. |
| `@Transactional` | service | 메서드 전체를 DB 트랜잭션 하나로 묶습니다. 중간에 예외가 나면 전부 취소(롤백). |
| 비관적 잠금 `PESSIMISTIC_WRITE` | RoomRepository | `SELECT ... FOR UPDATE`. 다른 트랜잭션은 이 방 행을 잠글 수 없어 기다립니다. 동시 제출을 순서대로 처리하는 장치. |
| 멱등성(idempotency) `requestId` | RoleService | 네트워크가 끊겨 같은 요청을 다시 보내도 결과가 한 번만 반영되게 하는 UUID. |
| `record` | dto | 값만 담는 불변 클래스를 한 줄로 만드는 자바 16+ 문법. getter는 `name()` 형태. |
| `Optional` | repository | "있을 수도, 없을 수도 있는 값". `orElseThrow`, `orElse(null)`로 꺼냅니다. |
| Stream (`filter/map/toList`) | service | 리스트를 한 줄씩 거르고 바꾸는 체인. SQL의 WHERE/SELECT와 비슷하게 읽으면 됩니다. |
| `ResponseStatusException` | service | 던지면 스프링이 그 HTTP 상태코드(400/403/404/409)로 응답합니다. |
| Flyway | resources/db/migration | `V1__`, `V2__` 순서로 SQL을 한 번씩 실행하고 기록합니다. 이미 실행된 파일은 **고치면 안 됩니다**(체크섬 오류). |
| `ddl-auto: validate` | application.yml | JPA가 테이블을 만들지 않고, 엔티티와 실제 테이블이 맞는지만 검사합니다. 테이블은 Flyway가 만듭니다. |

## 6. 식별자 헷갈리지 않기

| 이름 | 뜻 | 예 |
| --- | --- | --- |
| `userId` | 계정 번호. JWT의 `sub`에 들어 있음 | 100 |
| `playerId` | **방 안에서의** 플레이어 번호. 행동 대상(`targetPlayerId`)은 항상 이것 | 0, 1, 2… |
| `gamesId` = `roomsId` = `rooms.id` | 게임(방) 번호. URL에는 `gamesId`, 코드·DB에는 room | 12 |
| `nightNumber` = `roundNumber` | 라운드 번호. 첫 낮/첫 밤이 1, 낮→밤으로 넘어갈 때 +1 | 1 |

테스트에서는 `userId = 100 + playerId`로 맞춰 두었습니다. 그래서 `subject("103")`은 "3번 플레이어"라는 뜻입니다.
